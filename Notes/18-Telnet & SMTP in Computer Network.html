Telnet in Computer Network

Remote Terminal Access Protocol

Telnet is a client-server protocol used to establish text-based communication between a remote device (client) and a server. It operates over TCP/IP networks, usually on port 23.

Introduction to Telnet

The main task of the internet is to provide services to users. For example, users want to run different application programs at the remote site and transfer a result to the local site. This requires a client-server program such as FTP, SMTP. But this would not allow us to create a specific program for each demand.

The better solution is to provide a general client-server program that lets the user access any application program on a remote computer. Therefore, a program that allows a user to log on to a remote computer. A popular client-server program Telnet is used to meet such demands. Telnet is an abbreviation for Terminal Network.

Telnet provides a connection to the remote computer in such a way that a local terminal appears to be at the remote side.

Types of Login

Local Login

In a local login, the user sits at the terminal directly connected to the computer. The terminal driver passes the characters to the operating system, which interprets the characters and invokes the desired application program.

Remote Login

When the user wants to access an application program on a remote computer, the user must perform remote login. The user's terminal is connected to the local terminal driver, which then sends the characters to the TELNET client.

Remote login allows users to access and control a remote computer as if they were sitting directly in front of it, enabling remote administration and access to resources from anywhere in the world.

Step-by-Step Procedure of Remote Login

1

Local Input Capture

The process begins when a user types a command or text on their local computer's keyboard. The local machine's operating system accepts these individual keystrokes.

2

Client Handoff

Instead of interpreting the characters itself, the local operating system immediately sends them to a TELNET client software application running on the same machine.

3

Universal Translation by the Client

The TELNET client performs an important translation function. It converts locally formatted characters into a universal, standardized character set known as the Network Virtual Terminal (NVT) format.

4

Network Dispatch

The newly translated NVT characters are passed to the local computer's TCP/IP protocol stack. This software packages data into TCP segments and IP packets, preparing them for travel across the network.

Step-by-Step Procedure of Remote Login (Continued)

5

Network Transit and Reception

NVT-formatted commands travel over the Internet (or local network) and arrive at the remote computer, where they are received by its TCP/IP protocol stack.

6

Server-Side Delivery

The remote computer's TCP/IP stack reassembles the data and delivers the stream of NVT characters to its operating system. The operating system then forwards this data to the TELNET server process.

7

Remote System Translation

The TELNET server does the reverse translation for the client. It converts universal NVT characters into a format that the specific remote computer's operating system and applications can natively understand and process.

8

Terminal Emulation

Translated characters are passed through a pseudo-terminal driver. This software tricks the remote operating system into believing that the characters are coming from a physically connected terminal.

9

Application Execution

The remote operating system passes the characters to the appropriate application program, which processes the command as if it were entered locally. The output begins its journey back to the user along the same path in the opposite direction.

Network Virtual Terminal (NVT)

The network virtual terminal is an interface that defines how data and commands are sent across the network.

In today's world, systems are heterogeneous. For example, the operating system accepts a special combination of characters, such as end-of-file token running a DOS operating system, Ctrl-Z, while the token running a UNIX operating system is Ctrl-D.

TELNET solves this issue by defining a universal interface known as a network virtual interface.

The TELNET client translates the characters that come from the local terminal into NVT form and then delivers them to the network. The Telnet server then translates the data from NVT form into a form that can be understood by a remote computer.

Advantages of Telnet

Simple, Bidirectional Communication

At its core, Telnet is a straightforward tool for sending and receiving information. It creates a text-based, two-way communication channel between the client and the server.

Centralized Network Administration

Telnet allows remote management of network elements such as routers, switches, and servers. Instead of requiring physical access, an administrator can simply open a Telnet session to configure and troubleshoot.

Built-in User Authentication

The protocol includes a framework for user authentication, which requires a valid username and password to gain access. It provided a basic level of access control.

Universal Compatibility with NVT

The key to Telnet's success was the Network Virtual Terminal (NVT). It was a brilliant software solution that acted as a universal translator, ensuring seamless interaction between different types of computers.

Cost-effective Resource Sharing

Telnet enabled shared use of expensive, centralized resources. For example, a powerful mainframe computer can be housed in a single location and accessed by authorized users worldwide.

Disadvantages of Telnet

Serious Security Vulnerability

This is the most famous and serious disadvantage of Telnet. All data, including user ID and password, is transmitted in plain text. There is no encryption of any kind, making it vulnerable to packet sniffing.

Limited to Text Interface Only

Telnet is a character-based communication tool. It is fundamentally incapable of transmitting graphical information. You cannot run any graphical user interface (GUI) applications over a Telnet connection.

Protocol Inefficiency

From a technical perspective, Telnet is a relatively inefficient protocol. It was designed for a different era of networking and can be chatty and slow compared to modern alternatives.

High Overhead for Simple Tasks

The design of the protocol means that each keystroke you type generates network traffic and requires multiple internal context switches, leading to noticeable lag and a less responsive experience.

Hidden Costs of Low Speed

A combination of slow data transmission and inability to use modern graphical tools often results in slow completion of work, which can translate into higher labor costs and inefficiencies for businesses.

TELNET Commands and Options

Telnet operates using a specific command language that allows clients and servers to negotiate features and manage connections. These commands are separated from regular data by a special prefix.

Command Identifier: IAC

All TELNET commands are identified by a unique prefix character known as Interpret as Command (IAC). The decimal code of IAC is 255. When this byte appears in the data stream, it signals that the following byte is not regular data but a command or option interaction.

The basic format is a sequence of at least two bytes: IAC, followed by the command code.

The protocol uses a series of commands for option negotiation, where the client and server agree on how the connection will behave. The most important commands form a symmetric request/response system.

Core Telnet Negotiation Commands

1. WILL (decimal 251)

This command is used in two ways:

  • A party may send a "WILL" to enable a specific feature
  • It is also used to accept a request from the other party to enable a feature

2. WILL NOT (decimal 252)

This command is used to:

  • Reject the other party's request to enable a feature
  • Proposing to disable a feature
  • Accept the request to disable a feature

3. DO (decimal 253)

This command is used to:

  • Approve the other party's proposal to enable a feature ("WILL" command)
  • Request that the other party enable a specific feature

4. DO NOT (decimal 254)

This command is used to:

  • Reject the other party's offer to enable a feature
  • Approve the proposal to disable a feature
  • Request that the other party disable a feature

Common TELNET Options

These negotiation commands are used to enable or disable specific options that modify the behavior of the connection. The option is specified by a third byte in the sequence.

Code Option Meaning
0 Binary Switches the connection to 8-bit binary transmission
1 Echo Configures one side to echo back the data it receives from the other
3 Suppress Go Ahead Stops the transmission of "go ahead" signals after data
5 Status Requests the status of a TELNET option from the remote party
6 Timing Mark Used to insert a synchronization point in the data stream
24 Terminal Type Allows the server to request and learn the type of the client's terminal
34 Line Mode Switches the connection from character-at-a-time to full-line mode

TELNET Modes of Operation

TELNET supports various modes of operation that define how user input is managed and transmitted between the client and the server. Each mode provides different features for data processing and echo control.

Default Mode

The default mode serves as the fundamental operating state when no specific mode is activated:

  • Character echo is completely managed by client software
  • When a user types characters, they appear immediately on the local screen due to client-side echoing
  • The actual transmission to the server is delayed until the entire line is completed
  • This mode provides a responsive typing experience while reducing network traffic

Character Mode

Also known as character-at-a-time mode, this approach provides instant transmission:

  • Each character is sent to the server as it is typed
  • The server typically handles the echoing function
  • This creates a continuous conversation where each keystroke generates a round-trip
  • Can generate significant network overhead due to frequent transmission

Line Mode

Line mode provides a balanced approach between efficiency and functionality:

  • Extensive line editing features managed client-side
  • The client collects an entire line of input before transmitting it
  • This approach reduces network traffic by sending entire commands
  • Users benefit from local editing capabilities while servers get clean commands

Using a Command-line Interface

The most distinctive feature of Telnet is its command-line interface. Unlike modern software, which relies on a graphical user interface (GUI), Telnet requires users to manually type text-based commands at a prompt.

Although this approach may seem daunting initially, it becomes remarkably efficient once users become familiar with the syntax and workflow. To find available commands, users can type "help" and press Enter to display a detailed list.

Configuration changes and parameter adjustments on a remote device or server are accomplished by navigating through a hierarchical menu system using specific text commands.

It is important to recognize that Telnet was designed primarily for interacting with servers and networking equipment, rather than for everyday desktop applications or web browsing.

As a result, most Telnet commands are technical in nature, focused on system administration and network management tasks.

Sending and Receiving Data Through TELNET

The primary function of TELNET is to facilitate two-way data transmission between a local device and a remote server. Once the connection is established, users can input commands through their local command-line interface, which are then executed by the remote server.

This mechanism enables efficient communication with networking devices and servers from any location with network access. A practical example: When an IT administrator needs to remotely modify configuration settings on a router, they can establish a Telnet connection and input commands as if they were physically connected to the device.

Although this remote administration capability provides significant convenience, it is important to acknowledge a fundamental security limitation of Telnet: all data transmission occurs without encryption. This vulnerability exposes sensitive information, including login credentials and configuration details, to potential interception during transmission.

Therefore, network administrators should implement additional security measures, such as authentication protocols and encryption technologies, or consider switching to more secure alternatives, such as SSH.

FAQs - Telnet

1. What is Telnet, and how does it work?
Telnet (short for Terminal Network) is a protocol used to remotely access and manage devices on a network. It works by creating a virtual terminal connection between the client and the server. When a user types commands locally, Telnet translates them into a standard format (Network Virtual Terminal or NVT), sends them over the Internet, and allows the remote server to interpret and execute them.
2. What are the main differences between local login and remote login using Telnet?
Local login: The user interacts directly with the local computer's operating system and applications. Remote login (via Telnet): The user accesses a remote machine as if they existed locally on that system. Keystrokes are sent over the network using Telnet, translated via NVT, and interpreted by the remote system.
3. Why is Telnet considered insecure for modern networks?
Telnet transmits all data, including usernames and passwords, in plain text without encryption. This makes it highly vulnerable to packet sniffing and man-in-the-middle attacks. For this reason, Telnet has been largely replaced by secure alternatives such as SSH (Secure Shell).
4. What are the main benefits of using Telnet?
Simple, two-way text-based communication; Remote administration of network devices; Built-in user authentication; Compatibility across all systems using Network Virtual Terminal (NVT); Cost-effective sharing of centralized resources.
5. What are the common Telnet commands used for option negotiation?
Telnet uses a special command system identified by IAC (Interpret as Command). Common commands include: Will (251) to make or accept an offer to enable a feature; Won't (252) to deny or disable a feature; Do (253) to approve or request enabling a feature; Don't (254) to reject or request disabling a feature.

Simple Mail Transfer Protocol (SMTP)

The Standard Protocol for Email Transmission

SMTP (Simple Mail Transfer Protocol) is a standard communication protocol used to send emails from one server to another via the Internet. It defines how email messages are formatted, transmitted, and delivered between mail servers.

The main purpose of SMTP is to set up communication rules between servers. The servers have a way of identifying themselves and announcing what kind of communication they are trying to perform. They also have a way of handling errors such as incorrect email addresses.

For example, if the recipient address is wrong, then the receiving server replies with an error message of some kind.

Components of SMTP

First, we break the SMTP client and SMTP server into two components such as user agent (UA) and mail transfer agent (MTA).

📧

User Agent (UA)

The user agent (UA) prepares the message, creates the envelope and then puts the message in the envelope.

🔄

Mail Transfer Agent (MTA)

The mail transfer agent (MTA) transfers this mail across the internet.

SMTP allows a more complex system by adding a relaying system. Instead of just having one MTA at sending side and one at receiving side, more MTAs can be added, acting either as a client or server to relay the email.

The relaying system without TCP/IP protocol can also be used to send the emails to users, and this is achieved by the use of the mail gateway. The mail gateway is a relay MTA that can be used to receive an email.

Working of SMTP

1

Composition of Mail

A user sends an e-mail by composing an electronic mail message using a Mail User Agent (MUA). The message contains two parts: body and header. The body is the main part of the message while the header includes information such as the sender and recipient address.

2

Submission of Mail

After composing an email, the mail client then submits the completed e-mail to the SMTP server by using SMTP on TCP port 25.

3

Delivery of Mail

E-mail addresses contain two parts: the username of the recipient and the domain name. It refers to how an email message is transferred and delivered from the sender's mail server to the recipient's mail server.

4

Receipt and Processing of Mail

Once the incoming message is received, the exchange server delivers it to the incoming server (Mail Delivery Agent) which stores the e-mail where it waits for the user to retrieve it.

5

Access and Retrieval of Mail

The stored email in MDA can be retrieved by using MUA (Mail User Agent). MUA can be accessed by using login and password.

Applications of SMTP

Today, SMTP is used by almost every email system worldwide. Primary email providers, like Gmail or Outlook, and Yahoo, build on strong SMTP architectures, sending and relaying billions of messages every day. Users can access these accounts using the mail servers.

Popular SMTP Servers:

  • Sendmail: One of the oldest and most widely used mail transfer agents
  • Postfix: Known for security, performance, and easy configuration
  • Microsoft Exchange Server: Commonly used in corporate environments
  • Exim: Flexible and suitable for Unix-like systems
  • Qmail: Focused on simplicity and reliability

SMTP servers use various certified integrated systems to incorporate spam filtering, antivirus software, and logging, ensuring safe and efficient mail delivery.

Types of SMTP Protocol

The SMTP model supports two types of delivery methods:

1. End-to-End Delivery

  • Applies to different organizations
  • Emails travel directly from the sender's SMTP client to the recipient's SMTP server, without any middle servers
  • The SMTP client remains on hold until a copy of the email is saved to the recipient's server

2. Store-and-Forward

  • Applying to inter- and intra-organizational TCP/IP-based networks
  • Emails can pass through several intermediate MTAs preceding the recipient
  • Emails are only sent to the sender after they are received at the primary server, not at the final one

The store-and-forward method is more common in modern email systems as it provides better reliability and allows for more complex routing paths.

Features of SMTP

Reliability

There is a guarantee that SMTP will successfully deliver messages to the right destination servers. In the rare instances that it doesn't, a return message is produced to inform the sender that there was a breakdown in the communication channel.

Store-and-Forward Service

SMTP also allows for the alternate delivery of messages. In cases where the recipient's server is down, it will still deliver the message as it will be saved and sent when the server is active.

Command and Response Structure

The simplicity of command/response interaction is a distinguishing characteristic of SMTP. Command sent by the client will always produce a corresponding response code from the server indicating delivery or the next step.

Support for Multiple Recipients

SMTP is capable of delivering the same message to multiple recipients at the same time. This facilitates group emailing and mailing lists.

Queue Management

SMTP servers are designed with the ability to manage message queues. If a message is unable to be sent, the server will place the message in the queue and attempt to resend at predetermined time intervals.

Extensibility

The implementation of ESMTP (Extended SMTP) allows for various new functionalities such as authentication, secure transactions, and improved management of oversized attachments.

Model of SMTP System

In the SMTP model:

  • Users utilize User Agents (UAs) like Outlook, Mozilla, etc.
  • Through TCP, Mail Transfer Agents (MTAs) take care of the mail exchange.
  • Local MTAs are set up by system admins, and MTAs are connected in such a manner that queued unsent emails are retried for delivery in the event of failed attempts.
  • MTAs are responsible for distributing emails to mailboxes that can be accessed by the users for later retrieval.

Core Components: Mail User Agent (MUA), Mail Submission Agent (MSA), Mail Transfer Agent (MTA), and Mail Delivery Agent (MDA) work together to ensure email delivery from sender to recipient.

The SMTP system follows a logical flow where the sender's MUA creates the email, which is then sent to the MSA, which passes it to the MTA. The MTA routes the email through the network to the recipient's MTA, which delivers it to the MDA for storage until the recipient retrieves it with their MUA.

Main Components

📨

Mail User Agent (MUA)

Sends and receives emails. This is the application that users interact with directly, such as Outlook, Thunderbird, or web-based email clients.

📤

Mail Submission Agent (MSA)

Accepts mail from MUA and sends it to MTA. It typically listens on port 587 for incoming submissions.

🔄

Mail Transfer Agent (MTA)

Transfers mail between servers using SMTP. It uses DNS MX records to find the recipient's mail server.

📬

Mail Delivery Agent (MDA)

Delivers mail to the local system/mailbox. It stores the email until the recipient retrieves it using POP3 or IMAP.

Common SMTP Commands

1. HELO / EHLO

The HELO command is used by the client to introduce itself to the SMTP server. EHLO (Extended HELO) is a newer version used in Extended SMTP to identify the client and request supported extensions.

Example: HELO mail.example.com

Server Response: 250 mail.example.com Hello

2. MAIL FROM:

This command specifies the sender's email address. It initiates a mail transaction.

Example: MAIL FROM:<[email protected]>

Server Response: 250 OK

3. RCPT TO:

Specifies the recipient of the email. Multiple RCPT TO commands can be used for multiple recipients.

Example: RCPT TO:<[email protected]>

Server Response: 250 OK

4. DATA

The DATA command indicates that the message content will follow. After issuing this command, the client sends the message body and ends it with a single period (.) on a line by itself.

Example: DATA

Server Response: 354 Start mail input; end with <CRLF>.<CRLF>

5. QUIT

Terminates the SMTP session. After this command, the connection is closed.

Example: QUIT

Server Response: 221 Bye

Extended SMTP (ESMTP)

With the increasing use of emails, the original SMTP protocol experienced inadequacies, particularly in terms of the need for authentication, security, and message size. To address these, the Extended SMTP (ESMTP) was designed as an advancement of the original protocol.

ESMTP introduces several new features:

SMTP Authentication (AUTH)

The SMTP Authentication (AUTH) feature allows users to log in before sending emails, which helps to prevent spam and the illicit use of mail servers.

Delivery Status Notifications (DSN)

The Delivery Status Notifications (DSN) allow senders to receive more comprehensive reports on the status of an email, including whether it was delivered, failed, or was delayed.

8BITMIME Support

The 8BITMIME capability allows for the sending of binary attachments and non-ASCII characters, which was not possible in the original SMTP.

STARTTLS Command

Users can encrypt their SMTP sessions, which enhances the privacy of emails and protects them from eavesdropping.

SIZE Extension

The SIZE extension allows servers to specify the maximum message size, which avoids excessively large messages.

Thus, ESMTP improves the security, flexibility, and efficiency of SMTP for the modern internet.

ESMTP is backward compatible with SMTP, and most modern email systems use ESMTP for its enhanced features and security capabilities.

SMTP Architecture and Flow

SMTP Flow and Architecture. Logical components of SMTP office architecture and systems ensure the office seamlessly passes messages for delivery:

📨

Mail User Agent (MUA)

This refers to the end-user applications that individuals utilize to craft, dispatch, and access emails (like Outlook or Thunderbird). It connects to an SMTP server when messages need to be sent.

📤

Mail Submission Agent (MSA)

This component accepts messages from the MUA; it performs primary checks to qualify gateway access and ensure the proper configuration of messages. It typically listens on port 587 for incoming submissions.

🔄

Mail Transfer Agent (MTA)

This component is tasked with the responsibility of relaying messages between email servers. By utilizing DNS MX records, the MTA identifies the recipients' email servers.

📬

Mail Delivery Agent (MDA)

The MDA receives messages from the MTA and delivers them to the recipient's mailbox for storage. Later, the MUA retrieves it via the POP3 or IMAP protocols.

🌐

Mail Gateway

This component connects disparate mail systems or networks. For example, it may transform SMTP messages for networks that do not utilize the TCP/IP protocol.

SMTP Ports and Their Usage

SMTP communication typically uses the following ports:

Port Purpose Encryption
25 Default SMTP port for message relay between mail servers May use STARTTLS
465 SMTP over SSL (SMTPS), used for encrypted communication Implicit SSL
587 Submission port used by mail clients to send messages securely STARTTLS supported

For server-to-server communication, port 25 is the standard, while for email submission, port 587 is preferred due to its spam prevention and security features.

Port 465 was originally assigned for SMTPS (SMTP over SSL), but its use has been deprecated in favor of using STARTTLS on port 587. However, some systems still support port 465 for backward compatibility.

Advantages of SMTP

Simplicity

The implementation and understanding of Simple Mail Transfer Protocol (SMTP) is easy, thus making it a preference for email communication. The design guarantees that there will be no interruptions during the transfer of messages between servers.

Interoperability

SMTP functions and communicates on various platforms, operating systems, and networks, thus ensuring communication between differing email clients and servers across the globe.

Scalability

The protocol works with a variety of customers, which can range from personal accounts to large organizations. It can manage extensive email communication, which is a valuable resource to large organizations.

Error Reporting

SMTP grants users and administrators the ability to understand and rectify problems on message delivery by providing a step-by-step guide on the error.

Extensibility

Enhanced SMTP (ESMTP) has been developed in a way to allow more modern extensions that enhance and diversify many functions. Such functions include authentication, encryption, and message queuing.

Security

The addition of TLS (Transport Layer Security) and authentication mechanisms has allowed SMTP to monitor and secure data.

Disadvantages and Limitations

Plain Text Transmission

Transmitting emails with no encryption can lead to the loss of sensitive data, as emails can be intercepted. While ESMTP supports encryption, basic SMTP does not.

Spam Issues

SMTP is quite open, and it can be abused by sending unsolicited and spam emails. This has led to the development of various anti-spam techniques and authentication mechanisms.

Limited Message Size

Attachment size limitations occur because many servers impose regulations on large file transfers. This can be problematic when sending large files or multimedia content.

Store-and-Forward Delays

Messages can also be delayed if intermediate mail servers are down or if they are overloaded with messages. This can result in significant delays in email delivery.

No Built-in Delivery Confirmation

The basic SMTP configuration does not include delivery receipts. Enhanced features like Delivery Status Notification (DSN) must be implemented for confirmation.

Despite these limitations, SMTP remains the foundation of email communication, with continuous improvements addressing many of these issues.

The Future of SMTP

Despite being decades old, the Simple Mail Transfer Protocol keeps advancing. New updates cater to security, authentication, and merging with the cloud.

Emerging trends include:

Using TLS for all transmissions will soon become the standard. This will help protect email content from interception and tampering.

1. What is SMTP, and why is it important?
SMTP is the Simple Mail Transfer Protocol. It is the digital communication protocol for email transmission. It is the protocol that specifies the structure of messages and the manner of transfer and relay of messages and servers. It provides the foundation on which dependable electronic mail communication is built.
2. How does SMTP work in the email-sending process?
SMTP is sequential and includes the following processes: composition, submission, transfer, reception, and retrieval. A Mail User Agent (MUA) composes and transmits an email through the Mail Submission Agent (MSA) on ports 25 or 587. A Mail Transfer Agent (MTA) relays the email through networks, using DNS MX records, until it arrives at the recipient's Mail Delivery Agent (MDA), which saves the email for retrieval.
3. What is the difference between SMTP and ESMTP?
ESMTP (Extended SMTP) is an improved variant of SMTP that has additional functionalities like authentication (AUTH), encryption (STARTTLS), control of message size (SIZE), and delivery status notifications (DSN). ESMTP is a more secure, more flexible, and more modern email system.
4. Which ports are commonly used in SMTP communication?
SMTP uses three ports. Port 25 is used for mail relay between servers. Port 465 is used for SMTPS (which is encrypted over SSL), and Port 587 is used for secure mail submission that employs STARTTLS. Port 587 is now the primary recommended port for authenticated email sending.
5. What are some common advantages and limitations of SMTP?
Some of the advantages are simplicity, interoperability, and scalability; it can also be extended through ESMTP. Some limitations are the lack of built-in encryption, insufficient delivery in case of server downtime, undesired spam, and message size restrictions.
