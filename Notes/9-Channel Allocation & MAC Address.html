Channel Allocation & MAC Address

Data Link Layer Advanced Topics

Understanding channel allocation schemes and MAC addresses is fundamental to managing network resources and ensuring proper communication between devices in computer networks.

Channel Allocation in Computer Networks

When there are more than one user who desire to access a shared network channel, an algorithm is deployed for channel allocation among the competing users. The network channel may be a single cable or optical fiber connecting multiple nodes, or a portion of the wireless spectrum.

Channel allocation algorithms allocate the wired channels and bandwidths to the users, who may be base stations, access points or terminal equipment.

Channel Allocation Schemes

Channel allocation may be done using two schemes:

Static Channel Allocation

A fixed portion of the frequency channel is allotted to each user. For N competing users, the bandwidth is divided into N channels using frequency division multiplexing (FDM), and each portion is assigned to one user.

Dynamic Channel Allocation

Frequency bands are not permanently assigned to the users. Instead channels are allotted to users dynamically as needed, from a central pool. The allocation is done considering a number of parameters so that transmission interference is minimized.

Dynamic channel allocation optimizes bandwidth usage and results in faster transmissions, while static allocation provides fixed channels without interference but may not be efficient for variable bandwidth requirements.

Static Channel Allocation

In static channel allocation scheme, a fixed portion of the frequency channel is allotted to each user. For N competing users, the bandwidth is divided into N channels using frequency division multiplexing (FDM), and each portion is assigned to one user.

This scheme is also referred to as fixed channel allocation or fixed channel assignment.

Characteristics

  • No interference between users since each user is assigned a fixed channel
  • Simple to implement
  • Not suitable for a large number of users with variable bandwidth requirements
  • Inefficient utilization of bandwidth when some users are inactive
  • Fixed allocation regardless of actual demand

Static channel allocation is most effective when the number of users is fixed and their bandwidth requirements are relatively constant.

Dynamic Channel Allocation

In dynamic channel allocation scheme, frequency bands are not permanently assigned to the users. Instead channels are allotted to users dynamically as needed, from a central pool.

The allocation is done considering a number of parameters so that transmission interference is minimized.

Advantages

  • Optimizes bandwidth usage
  • Results in faster transmissions
  • Adapts to varying traffic patterns
  • More efficient utilization of spectrum

Types

Centralized Allocation

A central controller manages channel allocation based on requests from users

Distributed Allocation

Users coordinate channel allocation among themselves without a central controller

Dynamic channel allocation is more complex to implement but provides better utilization of resources, especially in environments with varying traffic patterns.

MAC Address in Computer Networks

Media Access Control (MAC) address is a physical address that works at the data link layer of the OSI model.

A MAC address is a 48 or 64-bit address associated with a network adapter. MAC addresses are linked to the hardware of the network adapters, hence they are also known as the "hardware address" or "physical address."

MAC addresses uniquely identify the adapter on the LAN. MAC addresses are expressed in hexadecimal notation. For example, "01-23-45-67-89-AB" in a 48-bit address or "01-23-45-67-89-AB-CD-EF" in a 64-bit address. Sometimes, colons (:) are used instead of dashes (-).

MAC addresses are often considered permanent, but in some conditions, they can be changed.

Every network interface card (NIC) has a unique MAC address assigned by the manufacturer, which distinguishes it from all other devices on the network.

Types of MAC Addresses

There are three types of MAC addresses:

Unicast MAC Address

A unique address that identifies a specific network device for communication

Multicast MAC Address

An address that identifies a group of devices for simultaneous communication

Broadcast MAC Address

A special address that allows communication with all devices on the network

Understanding these different types of MAC addresses is essential for network configuration and security management.

MAC Address Format

A 48-bit MAC address is represented as a string of six octets, "MM:MM:MM:SS:SS:SS".

The first half (24 bits) of the MAC address contains the ID number of the adapter manufacturer. These IDs are regulated by an Internet standards organization.

The second half (24 more bits) of the MAC address represents the serial number assigned to the adapter by the manufacturer.

OUIs of some well-known manufacturers

  • "00-14-22" Dell
  • "00-04-DC" Nortel
  • "3C:5A: B4" Google, Inc.
  • "00-A0-C9" Intel corporation

The first three octets (OUI) identify the manufacturer, while the last three octets represent the specific device.

Error Control in Data Link Layer

Error control in data link layer is the process of detecting and correcting data frames that have been corrupted or lost during transmission.

In case of lost or corrupted frames, the receiver does not receive the correct data-frame and sender is ignorant about the loss. Data link layer follows a technique to detect transit errors and take necessary actions, which is retransmission of frames whenever error is detected or frame is lost. The process is called Automatic Repeat Request (ARQ).

Phases in Error Control

  • Detection of Error: Transmission error, if any, is detected by either the sender or the receiver
  • Acknowledgment: May be positive or negative
  • Positive ACK: On receiving a correct frame, the receiver sends a positive acknowledge
  • Negative ACK: On receiving a damaged frame or a duplicate frame, the receiver sends a negative acknowledgment
  • Retransmission: The sender maintains a clock and sets a timeout period. If an acknowledgment does not arrive before timeout, or a negative acknowledgment is received, the sender retransmits the frame

Error control mechanisms ensure reliable data transmission by detecting and correcting errors that may occur during transmission.

Error Control Techniques

There are three main techniques for error control:

Stop and Wait ARQ

Involves sending a frame and waiting for acknowledgment before sending the next frame

Go-Back-N ARQ

Sends multiple frames without waiting for acknowledgment and retransmits all frames after the last acknowledged frame if an error occurs

Selective Repeat ARQ

Sends only frames that are negatively acknowledged, reducing unnecessary retransmissions

Each technique offers different trade-offs between efficiency, complexity, and resource utilization.

Flow Control in Data Link Layer

Flow control is a technique that allows two stations working at different speeds to communicate with each other. It is a set of measures taken to regulate the amount of data that a sender sends so that a fast sender does not overwhelm a slow receiver.

In data link layer, flow control restricts the number of frames the sender can send before it waits for an acknowledgment from the receiver.

Approaches of Flow Control

Feedback based Flow Control

The sender sends frames after receiving acknowledgments from the user. This is used in the data link layer.

Rate based Flow Control

Protocols have built-in mechanisms to restrict the rate of transmission without requiring acknowledgment from the receiver. This is used in the network layer and the transport layer.

Flow control ensures that a fast sender does not overwhelm a slow receiver, preventing data loss and improving overall network efficiency.

Flow Control Techniques in Data Link Layer

Data link layer uses feedback based flow control mechanisms. There are two main techniques:

Stop and Wait

The sender sends a frame and waits for acknowledgment. Once the receiver receives the frame, it sends an acknowledgment frame back to the sender.

Sliding Window

Allows multiple frames to be transmitted before receiving an acknowledgment, improving efficiency over stop and wait.

Sliding Window Working Principle

  • Both the sender and the receiver has finite sized buffers called windows
  • The sender and the receiver agree upon the number of frames to be sent based upon the buffer size
  • The sender sends multiple frames in a sequence, without waiting for acknowledgment
  • When its sending window is filled, it waits for acknowledgment
  • On receiving acknowledgment, it advances the window and transmits the next frames

Sliding window protocol improves network efficiency by allowing multiple frames to be transmitted before requiring acknowledgment.

Framing in Data Link Layer

In the physical layer, data transmission involves synchronised transmission of bits from the source to the destination. The data link layer packs these bits into frames.

Data-link layer takes the packets from the Network Layer and encapsulates them into frames. If the frame size becomes too large, then the packet may be divided into small sized frames. Smaller sized frames makes flow control and error control more efficient.

Then, it sends each frame bit-by-bit on the hardware. At receiver's end, data link layer picks up signals from hardware and assembles them into frames.

Parts of a Frame

Frame Header
Payload field
Trailer
Flag

Types of Framing

Fixed-sized Framing

Size of the frame is fixed and acts as delimiter. Used in ATM cells.

Variable Sized Framing

Size of each frame may be different. Used in local area networks with byte stuffing or bit stuffing.

Framing is essential for organizing data into manageable units for transmission across the network.

Types of Framing

Two ways to define frame delimiters in variable sized framing are:

Length Field

A length field is used that determines the size of the frame. It is used in Ethernet (IEEE 802.3).

End Delimiter

A pattern is used as a delimiter to determine the size of frame. Used in Token Rings with byte stuffing or bit stuffing to avoid confusion.

Variable sized framing requires additional mechanisms to mark frame boundaries, while fixed sized framing simplifies frame detection.

Computer Network - Error Detection & Correction

There are many reasons such as noise, cross-talk etc., which may help data to get corrupted during transmission. The upper layers work on some generalized view of network architecture and are not aware of actual hardware data processing.

Hence, the upper layers expect error-free transmission between the systems. Most of the applications would not function expectedly if they receive erroneous data.

Data-link layer uses some error control mechanism to ensure that frames (data bit streams) are transmitted with certain level of accuracy.

Types of Errors

Single Bit Error

Only one bit is corrupted in a frame

Multiple Bits Error

Frame is received with more than one bit corrupted

Burst Error

Frame contains more than one consecutive corrupted bits

Error control mechanism may involve error detection and correction, with different techniques suited to different types of errors.

Error Detection

Errors in the received frames are detected by means of Parity Check and Cyclic Redundancy Check (CRC). In both cases, few extra bits are sent along with actual data to confirm that bits received at other end are same as they were sent.

Parity Check

One extra bit is sent along with the original bits to make number of 1s either even in case of even parity, or odd in case of odd parity.

Cyclic Redundancy Check (CRC)

CRC is a different approach to detect if the received frame contains valid data. This technique involves binary division of the data bits being sent. The divisor is generated using polynomials.

CRC Process

Sender calculates remainder
Adds remainder to data
Transmits codeword

CRC is more powerful than parity check and can detect more types of errors with higher accuracy.

Error Correction

In the digital world, error correction can be done in two ways:

Backward Error Correction

When the receiver detects an error, it requests back the sender to retransmit the data unit.

Forward Error Correction

When the receiver detects an error, it executes error-correcting code to auto-recover and correct some kinds of errors.

Forward Error Correction is used in wireless transmission where retransmission may be expensive.

Error Correcting Codes

Error-correcting codes (ECC) are a sequence of numbers generated by specific algorithms for detecting and removing errors in data transmitted over noisy channels.

Types of Error Correcting Codes

Block Codes

Message is divided into fixed-sized blocks, with redundant bits added for error detection or correction.

Convolution Codes

Message comprises data streams of arbitrary length with parity symbols generated by sliding application of Boolean function.

Error correcting codes ascertain the exact number of bits that has been corrupted and the location of the corrupted bits, enabling forward error correction at the receiver.

Hamming Codes

Hamming codes are block codes that are capable of detecting up to two simultaneous bit errors and correcting single-bit errors.

Hamming Code Features

  • Uses redundant bits to both detect and correct errors
  • Can correct single-bit errors automatically
  • Requires specific mathematical calculations to determine parity bits
  • Named after Richard Hamming, who developed the technique

Applications

  • Computer memory systems
  • Satellite communications
  • Modems
  • Data storage systems

Hamming codes provide an efficient method for error detection and correction in digital communication systems.

Binary Convolution Code

Binary Convolution Code is an error-correcting code where an encoder processes an input sequence of bits of arbitrary length and generates a sequence of output bits.

Key Features

  • Message comprises of data streams of arbitrary length
  • Parity symbols are generated by sliding application of a Boolean function to the data stream
  • Provides good error correction capabilities
  • Used in wireless communications, deep space communications, and mobile communications

Advantages

  • Better error correction performance than block codes
  • Suitable for continuous data streams
  • Can handle burst errors effectively

Binary Convolution Codes are particularly useful in applications where data is transmitted continuously rather than in discrete blocks.

Reed-Solomon Code

Reed-Solomon codes are block codes that are capable of correcting burst errors in the received data block.

Key Features

  • Particularly effective at correcting burst errors
  • Widely used in storage systems
  • Digital communication systems
  • CD and DVD technologies
  • QR codes

Applications

  • Data storage systems
  • Wireless communications
  • Digital television broadcasting
  • Barcode scanning

Reed-Solomon codes are particularly valuable for systems where errors tend to occur in bursts rather than randomly distributed single-bit errors.

Low-Density Parity Check Code

Low-Density Parity Check (LDPC) is a block code specified by a parity-check matrix containing a low density of 1s.

Key Features

  • Suitable for large block sizes in very noisy channels
  • Efficient error detection and correction capabilities
  • Used in satellite communications
  • Digital television broadcasting
  • Wireless communications

Error-Detecting Codes - Parity Bits

For error detection, the sender needs to send some additional bits along with the data bits. The receiver performs necessary checks based upon the additional redundant bits.

There are three main techniques for detecting errors in data frames: Parity Check, Checksum and Cyclic Redundancy Check (CRC).

Parity Bits

The parity check is done by adding an extra bit, called parity bit, to the data to make the number of 1s either even or odd depending upon the type of parity.

Types of Parity

Even Parity

Here the total number of bits in the message is made even.

Odd Parity

Here the total number of bits in the message is made odd.

Error Detection Process

Sender counts 1s
Adds parity bit
Transmits frame
Receiver receives frame
Counts 1s
Checks parity

Parity check is simple to implement but can only detect odd numbers of bit errors, making it less reliable for detecting multiple bit errors.

Conclusion

Understanding channel allocation schemes, MAC addresses, and error control mechanisms is fundamental to implementing reliable and efficient data communication networks.

Each of these components plays a crucial role in ensuring that data is transmitted accurately and efficiently across the network.

Proper implementation of these concepts enables network engineers to design robust networks that can handle the demands of modern applications and services.

Together, these technologies form the foundation of data communication at the data link layer, bridging the gap between physical transmission and network layer protocols.
