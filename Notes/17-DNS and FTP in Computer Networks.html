DNS and FTP in Computer Networks

Domain Name System and File Transfer Protocol

A comprehensive overview of two fundamental protocols in computer networking: DNS for translating domain names to IP addresses, and FTP for transferring files between systems.

Introduction to DNS

DNS stands for Domain Name System, which is used in computer networks (especially the Internet) to translate human-readable domain names (like www.Tpointtech.com) into IP addresses (like 142.250.190.14) that computers use to identify each other on a network.

When you type a website name in your browser, the DNS acts like a phone book of the Internet. It helps your computer find the correct server by converting the domain name into its corresponding IP address.

DNS is a directory service that provides a mapping between the name of a host on the network and its numerical address. It is required for the functioning of the internet.

Each node in a tree has a domain name, and a full domain name is a sequence of symbols specified by dots.

DNS Domain Types

The domain name space is divided into three different sections: generic domains, country domains, and inverse domain.

Generic Domains

It defines the registered hosts according to their generic behavior. Each node in a tree defines the domain name, which is an index to the DNS database. It uses three-character labels that describe the organization type.

Country Domain

The format of country domain is the same as a generic domain, but it uses two-character country abbreviations (e.g., us for the United States) in place of three-character organizational abbreviations.

Inverse Domain

The inverse domain is used for mapping an address to a name. When the server has received a request from the client, and the server contains the files of only authorized clients, it sends a query to the DNS server to ask for mapping an address to the name.

DNS Lookup and Resolver

DNS Lookup

The process of converting a human-readable domain name, such as www.tpointtech.com, into its matching IP address, such as 192.0.2.1, which computers use to find and connect with one another on the internet, is known as DNS Lookup. It is also called DNS Resolution.

When a user enters a domain name into their browser, DNS Lookup starts. The query passes through servers like the DNS resolver, Root server, TLD server, and authoritative server. After locating the IP address, the browser establishes a connection with the website's server and loads the page.

DNS Resolver

Simply referred to as a DNS Client, a DNS Resolver is capable of starting the process of DNS Lookup. The DNS Resolver makes it simple for apps to access various websites and services on the Internet by utilizing user-friendly domain names, which also resolves the problem of remembering IP addresses.

Types of DNS Queries

The DNS Queries occur in DNS Lookup, which are basically of three types that define how this communication takes place:

Recursive Query

In a recursive query, the DNS client requests the DNS server to provide a complete answer - either the IP address of the requested domain or an error message. The DNS server takes full responsibility for querying other servers if needed until it finds the final answer.

Iterative Query

In an iterative query, the DNS server does not fetch the complete answer itself. Instead, if it doesn't have the information, it responds with a referral, the address of another DNS server that might know the answer. The client then continues querying these servers one by one until it gets the result.

Non-Recursive Query

When a DNS resolver asks a DNS server for a record that it has access to due to a record that is in its cache, this is known as a non-recursive query.

DNS Caching and TTL

DNS Caching

DNS Caching is the process of storing DNS query results temporarily on a device or DNS server. When you revisit a website, your system can use the cached DNS record instead of performing a new DNS lookup, saving time and improving performance.

TTL (Time-to-Live)

TTL is a setting in DNS records that defines how long a DNS record should be stored in the cache before it expires and needs to be refreshed from the authoritative DNS server.

  • TTL is measured in seconds
  • A lower TTL means more frequent updates (useful when DNS records change often)
  • A higher TTL improves speed but delays propagation of changes

For example, if the TTL for www.example.com is 3600 seconds, the item is cached for one hour before a new lookup is required.

DNS Security and DNSSEC

The Domain Name System (DNS) is a crucial part of the internet, but traditional DNS was not designed with strong security features, making it vulnerable to various attacks such as DNS spoofing or cache poisoning.

DNS Security Extensions (DNSSEC)

To protect DNS data integrity and authenticity, the DNS Security Extensions (DNSSEC) were introduced:

  • This protocol was created to solve security issues in DNS
  • It enables resolvers to verify the integrity and authenticity of DNS answers by including cryptographic signatures to DNS entries
  • DNSSEC ensures that the data a user gets back from a DNS query has not been changed

By comprehending DNSSEC, students can help protect websites from DNS-based attacks and guarantee secure and genuine browsing experiences.

Reverse DNS Lookup

A Reverse DNS Lookup (rDNS) is the process of finding the domain name associated with a given IP address. This is the reverse of a normal DNS lookup, which resolves a domain name to an IP address.

Typical Uses for Reverse DNS:

  • Email spam filtering
  • Network troubleshooting
  • Logging and analytics
  • Server authentication

Reverse DNS is particularly useful for email servers to verify that incoming mail is coming from a legitimate server. Many email systems will reject messages from servers that don't have proper reverse DNS records.

DNS Record Types

A DNS record is an entry in the DNS database that tells the internet how to handle requests for a domain name. Each record type defines a specific function:

A

A Record

Maps an IPv4 address to a domain name (e.g., tpointtech.com to 185.197.109.153). It is the most popular DNS record, used for directing a domain to the IP address of its website.

CNAME

CNAME Record

Maps one domain name (alias) to another domain name (canonical name). For instance, www.tpointtech.com can be an alias for tpointtech.com.

MX

MX Record

Tells the internet where to deliver emails for a particular domain. It specifies the mail server responsible for handling incoming emails.

TXT

TXT Record

Stores text-based data, frequently used to implement email security protocols like DKIM and SPF and to confirm domain ownership.

DNS Caching Locations

DNS caching occurs at multiple levels to improve performance and reduce DNS query traffic:

Browser DNS Caching

Web browsers are developed by default to cache DNS records for a set amount of time. The browser cache is the first location looked up for the requested record when a request is made for a DNS record.

Operating System (OS) Level DNS Caching

Your computer's operating system stores recently resolved domain name to IP address mappings in memory. This helps speed up future requests to the same domains without needing to query the DNS server again.

A "stub resolver" or DNS client is the term used to describe the operating system process designed to handle this query.

A stub resolver first determines whether it has the record in its own cache before responding to a request from an application. If not, it sends a DNS query to a DNS recursive resolver within the Internet service provider (ISP) outside the local network.

Introduction to FTP

FTP stands for File Transfer Protocol. It is a standard network protocol used to transfer files between a client and a server over a TCP/IP network such as the Internet or a local network.

FTP is a standard communication protocol. There are also other protocols, such as HTTP, which are used to move files between computers, but they are less focused and clear as compared to FTP.

Key Points of FTP:

  • FTP is a standard internet protocol provided by TCP/IP used for transmitting files from one host to another
  • It is mainly used for transferring web page files from their creator to the computer that acts as a server for other computers on the internet
  • It is also used for downloading files to a computer from other servers

Why FTP and Its Mechanism

Why FTP?

Although transferring files from one system to another is simple, it can cause problems:

  • Two systems may have different file conventions
  • Two systems may have different ways to represent text and data
  • Two systems may have different directory structures

FTP protocol overcomes these problems by establishing two connections between hosts: one for data transfer and another for the control connection.

Mechanism of FTP

FTP Connection Types

There are two types of connections in FTP:

Control Connection

The control connection uses very simple rules for communication. Through the control connection, we can transfer a line of command or line of response at a time. The control connection is made between the control processes and remains connected during the entire interactive FTP session.

Data Connection

The Data Connection uses very complex rules as data types may vary. The data connection is made between data transfer processes. The data connection opens when a command comes for transferring the files and closes when the file is transferred.

This dual-connection approach allows FTP to separate control information from actual data transfer, improving efficiency and reliability.

FTP Clients and Advantages/Disadvantages

FTP Clients

FTP client is a program that implements a file transfer protocol which allows you to transfer files between two hosts on the internet. It allows a user to connect to a remote host and upload or download files.

The FTP program is also available as a built-in component in a Web browser. This GUI-based FTP client makes file transfer very easy and does not require remembering FTP commands.

Advantages of FTP

  • Speed: One of the fastest ways to transfer files
  • Efficient: No need to complete all operations to get the entire file
  • Security: Requires login with username and password
  • Back & forth movement: Allows transferring files in both directions

Disadvantages of FTP

  • Not all FTP providers offer encryption
  • File size limit of 2GB
  • Passwords and file contents are sent in clear text
  • Not compatible with every system

Once the FTP connection is activated, the client and server communicate with each other by a specific sequence of commands and corresponding responses. The client issues commands, and the server answers with a number corresponding to the request status.

FTP Modes of Operation

An FTP server can work in either an Active or Passive Mode. They differ mainly in how each connection is set up.

🔴

Active Mode

An FTP client in Active Mode opens a random port (above 1023) and tells the server the port number with the PORT command. Then the server opens a connection from port 20 to the client's defined port to set up the data connection.

Control Connection: Client → Server (Port 21)
Data Connection: Server → Client (Port 20)

This method is ideal when the client's firewall is not set to block incoming connections.

🔵

Passive Mode

This Mode is used to bypass firewall restrictions. Here, the server randomly opens a port for data transfer and tells the client the port number using the PASV command. The client then initiates the connection to that port, establishing the data connection.

Control Connection: Client → Server (Port 21)
Data Connection: Client → Server (Random Port)

Most FTP clients today default to Passive Mode, which is more effective in the presence of firewalls and NAT devices.

Types of FTP

There are different types of FTP based on how authentication and encryption are handled:

1. Anonymous FTP

In this type of FTP, there is no requirement to have a user-specific login. Anyone can log into the server using a generic username ("anonymous") and an email address as a password. It is mainly used for public file sharing when the security level is negligible.

2. Password-Protected FTP

In this type, users are required to log in with a specified username and password, which ensures that only authorized users can access the server.

3. Secure FTP (SFTP)

It is important to note that SFTP (SSH File Transfer Protocol) is not the same as FTP. SFTP operates over the Secure Shell (SSH) protocol and provides encryption for commands and data, ensuring confidentiality and integrity in file transfers.

4. FTP Secure (FTPS)

FTPS expands the conventional FTP functionality by integrating Transport Layer Security (TLS) or Secure Sockets Layer (SSL) encryption. Depending on how the security layer is engaged, it can function in implicit or explicit modes.

FTP Architecture

The File Transfer Protocol (FTP) follows a client-server model where the client starts the conversation and the server listens to the requests.

FTP Client

Requests file operations (like uploading, downloading, or listing a directory) and presents the output to the user.

Components:
  • User Interface (UI): The graphical or command-line interface
  • Control Process: Manages the administrative link
  • Data Transfer Process: Manages the data connection

FTP Server

Responds, verifies the client's user credentials, and executes the requested file operations.

Components:
  • Server Control Process: Listens for connections, authenticates users
  • Server Data Transfer Process: Facilitates uploading, downloading, and directory listing

Security Issues in FTP

The original FTP design was implemented with little concern for security. Consequently, the original FTP protocol passes data, including usernames, passwords, and file data, in unprotected plain text:

Eavesdropping

FTP lacks encrypted traffic, so unprotected sensitive data may be intercepted by malicious actors monitoring the network connection.

Brute Force Attacks

FTP accounts may be accessed with unprotected passwords, and file data may be fraudulently accessed through repeated login attempts.

Data Integrity Issues

Losing file data in transit may go undetected. The original FTP protocol may relay lost packets without being detected, irrespective of transmission.

Firewall Conflicts

The active mode and multi-connection features of FTP can complicate reliable firewall security configurations.

Applications of FTP

FTP is commonly used in multiple industries and organizations for many purposes:

  • Website Management: Web developers send pages, images, and scripts to web servers using FTP, helpful for website updating and maintenance
  • Data Backup: Organizations routinely back up important files to remote servers or to the cloud
  • Software Distribution: Software vendors distribute updates and patches through FTP servers
  • Collaboration: FTP enables the sharing of files between geographically distant teams working on a common project
  • Education and Research: FTP servers are used to facilitate the exchange of large datasets and academic work in universities and research organizations
  • Media and Entertainment: FTP is used for large file transfers in video and audio production, as well as for the transfer of graphics and sound files

Future of FTP

Because of advancements in cybersecurity, traditional FTP is being phased out and replaced with secure versions of FTP, such as SFTP and FTPS. However, due to simplicity, reliability, and almost universal support, FTP still performs many invaluable functions.

Key Developments in Modern FTP Systems:

Integration with Cloud Services

Many FTP systems now interface with cloud systems such as AWS, Azure, and Google Cloud for hybrid data management.

Automation

Automation of uploads and downloads using scripts and tools like WinSCP, FileZilla, and cURL increases efficiency.

Enhanced Security

Modern systems protect data using 2FA and secure tunneling.

Web-Based FTP Clients

Available browser-based FTP interfaces lessen the need for dedicated software, making access easier and more portable.

Conclusion and FAQs

Conclusion

The Domain Name System (DNS) and File Transfer Protocol (FTP) are fundamental components of computer networking. DNS acts as the "phonebook for the internet," translating human-readable domain names into machine-readable IP addresses, while FTP provides a reliable method for transferring files between systems.

Q1. What is FTP, and how does it work?
File Transfer Protocol (FTP) is an Internet-based protocol to transfer files from one system to another over a TCP/IP network. It is based on a client-server architecture whereby one system, the client, requests file operations and the other system, the server, responds.
Q2. What are the main differences between FTP, SFTP, and FTPS?
FTP is the least secure because it sends data in plain text. SFTP operates over SSH and provides encryption for commands and data. FTPS places SSL/TLS encryption over standard FTP.
Q3. What security measures should be taken while using FTP?
Always use SFTP or FTPS over plain FTP, use strong passwords, enable 2FA, and keep the FTP software updated. Also, disabling anonymous access and setting restrictive directory permissions assist in securing log access.
