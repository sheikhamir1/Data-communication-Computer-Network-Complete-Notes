Network Layer & Addressing

Comprehensive Guide to OSI Layer 3 and Network Addressing

The Network Layer (Layer 3) is the third layer of the OSI model, responsible for handling the delivery of data packets from source to destination across multiple networks.

This presentation covers the fundamental concepts of network layer operations, protocols, and addressing schemes that form the backbone of modern computer networks.

Network Layer Overview

The Third Layer of the OSI Model

What is the Network Layer?

The Network Layer is the third layer of the OSI (Open Systems Interconnection) model. Its main role is to handle the delivery of data packets from the source device to the destination device across multiple networks.

Unlike the Data Link Layer, which deals with communication between directly connected nodes, the Network Layer ensures end-to-end delivery even if the devices are located in different networks.

It is responsible for logical addressing, routing, and path determination so that data can travel efficiently through intermediate devices like routers.

Key Differentiator

The Data Link Layer handles communication between directly connected nodes, while the Network Layer enables communication across different networks, regardless of their physical infrastructure.

Core Responsibilities: Logical Addressing

Hierarchical Addressing for Network Communication

Understanding Logical Addressing

Unlike the data link layer, which uses MAC addresses that are unique and hardwired within the local area network, these addresses will not suffice for communication between different networks.

IP Address Format

The network layer comes up with logical addressing, which is expressed in IP address format (e.g., IPv4 or IPv6). Logical addresses are hierarchical, which is advantageous as one is able to pinpoint not only the particular device but the network to which it is attached.

Examples of IP Addresses:

  • IPv4 address: 192.168.1.10
  • IPv6 address: 2001:0db8:85a3:0000:0000:8a2e:0370:7334

Logical addressing enables subnetting, supernetting, and routing across different and interrelated networks.

Core Responsibilities: Routing

Finding the Optimal Path for Data Transmission

What is Routing?

Routing determines the optimal route that a packet should take from the source to the destination. Since there is more than one path available for a packet to take to the destination, routers will have to choose which path to take based on cost, distance, congestion, and even administrative policies.

Static Routing

The routes are more often than not set manually, and the network administrators have to ensure that they are maintained. It is the most simplistic approach, but very rigid, as the set routes do not take into consideration the possibility of network failure or the changes that may occur to the network topology.

Dynamic Routing

Utilizes specific routing protocols so that routers learn and update routes automatically, maintaining adaptability and efficiency. Dynamic routing lessens the administrative burden and improves fault tolerance.

Examples of Dynamic Routing Protocols:

  • RIP (Routing Information Protocol)
  • OSPF (Open Shortest Path First)
  • BGP (Border Gateway Protocol)

Core Responsibilities: Forwarding

Actual Movement of Packets Through the Network

Understanding Forwarding

Forwarding is the actual movement of packets from one interface of a router to the designated interface for the packet based on the router's table. Unlike routing, which is the determination of the path, forwarding is the actual sending of packets to the path that the packet is supposed to travel.

Example:

When a router receives a packet that is addressed to 172.16.10.5, the router goes to its forwarding table. This table could indicate that packets that are addressed to the 172.16.0.0/16 network should be sent through the interface GigabitEthernet0/1. The router, therefore, sends the packet to the user.

Forwarding Table Construction

Forwarding tables are constructed using:

  • Longest Prefix Match (LPM): Having absolute clarity on what route to take is essential.
  • Next-Hop Information: The address of the subsequent router on the route.

Core Responsibilities: Fragmentation and Reassembly

Handling Variable Packet Sizes Across Networks

Maximum Transmission Unit (MTU)

Networks have different maximum Transmission Units (MTU) - the largest packets that can be sent. When a package is greater than the MTU of the network it passes through, it has to be fragmented into units.

Fragmentation

Begins from the sender or through the routers. The packets are divided into small fragments, each of which contains a piece of the original payload with headers that have sequential and reassembly identification.

Reassembly

Takes place on the destination host, where fragmented packets are collected to form the initial packet.

An illustration is a 4000-byte packet that can be sent through a link that has an MTU of 1500 bytes. That packet is fragmented into smaller packets to be sent.

Core Responsibilities: Internetworking

Connecting Different Networks Together

What is Internetworking?

The internet is a network made of numerous networks. The third layer is the most critical when it comes to tying different networks together that have varying physical and data link technologies. Internetworking permits seamless connectivity to different network types such as Ethernet, Wi-Fi, MPLS, and cellular.

The IP protocol also forms the backbone of internetworking, where it is used to facilitate inter-device communication irrespective of the devices' underlying structural frameworks.

Benefits of Internetworking

  • Enables communication between devices on different networks
  • Provides a unified addressing scheme across heterogeneous networks
  • Allows for seamless data transmission across network boundaries
  • Supports the global infrastructure of the internet

Core Responsibilities: Traffic Control

Managing Network Congestion

Understanding Network Congestion

Network Congestion is the result of bandwidth demand exceeding available capacity, which can result in packet loss, delays, and decreased network performance.

Congestion Management Techniques

Congestion is managed at the network layer using the following techniques:

  • Queuing: Saving packets in buffers within the router.
  • Traffic Shaping: Monitoring and control of data packet flows to control abrupt flows of packets.
  • Priority Handling: Assigning varying degrees of importance to traffic, for example, voice data and bulk data traffic.
  • Congestion Notification: Notification sent to endpoints by routers to lower the transmission rate, e.g., ECN - Explicit Congestion Notification.

Effective congestion management ensures optimal network performance and quality of service for different types of traffic.

Forwarding & Routing Mechanism

How Routers Process Packets

Router Forwarding Process

In Network layer, a router is used to forward the packets. Every router has a forwarding table. A router forwards a packet by examining a packet's header field and then using the header field value to index into the forwarding table.

Example:

The router with a header field value of 0111 arrives at a router, and then router indexes this header value into the forwarding table that determines the output link interface is 2. The router forwards the packet to the interface 2.

Routing Algorithm Role

The routing algorithm determines the values that are inserted in the forwarding table. The routing algorithm can be centralized or decentralized.

The value stored in the forwarding table corresponding to the header field value indicates the router's outgoing interface link to which the packet is to be forwarded.

Services Provided by the Network Layer

Essential Services for Network Communication

Key Network Layer Services

Guaranteed Delivery

This layer provides the service which guarantees that the packet will arrive at its destination.

Guaranteed Delivery with Bounded Delay

This service guarantees that the packet will be delivered within a specified host-to-host delay bound.

In-Order Packets

This service ensures that the packet arrives at the destination in the order in which they are sent.

Guaranteed Max Jitter

This service ensures that the amount of time taken between two successive transmissions at the sender is equal to the time between their receipt at the destination.

Security Services

The network layer provides security by using a session key between the source and destination host. The network layer in the source host encrypts the payloads of datagrams being sent to the destination host. The network layer in the destination host would then decrypt the payload. In such a way, the network layer maintains the data integrity and source authentication services.

Protocols of the Network Layer

Protocols that Power Network Communication

Numerous protocols operate at the network layer, and each of them is intended for specific functions that facilitate communication across networks:

Internet Protocol (IP)

IPv4: A globally used 32-bit addressing framework. It offers logical addressing and routing, but suffers from address space exhaustion.

IPv6: A 128-bit addressing scheme aimed to replace IPv4 exhaustion. It offers enhanced routing and security with a vast address space.

ICMP (Internet Control Message Protocol)

Used mainly for diagnostics and reporting errors. Tools like ping and traceroute use ICMP to monitor network connections and find possible routing problems.

IGMP (Internet Group Management Protocol)

Manages hosts' memberships to multicast groups for efficient streaming and other multicast data.

IPsec (Internet Protocol Security)

Contacts and manages a network by encrypting, authenticating, and checking for communication integrity at a lower level. Commonly used in VPNs.

ARP (Address Resolution Protocol)

Used in local networks, translates a logical IP address to a physical MAC address to allow smooth communication on a network.

Routing Algorithms

Finding Efficient Paths for Data Transmission

Algorithms are in charge of finding efficient routes for data packets to and from a source and a destination. While each has its own different method, all of them aim to enhance the network's performance and reliability. Major categories include:

1. Distance Vector Routing

Example: RIP (Routing Information Protocol)

Routers, at intervals, share distance vectors with their immediate neighbours. Each vector tells of the number of hops needed to get to a network. Distance vector routing is simple and easy to use, but can suffer from slow convergence and/or routing loops.

2. Link State Routing

Example: OSPF (Open Shortest Path First)

All the routers in the network communicate defined states of the links, where each router constructs a complete topology and for each performs the shortest-path algorithm using the Dijkstra method. This method is more precise and converges faster than the distance vector method.

3. Path Vector Routing

Example: BGP (Border Gateway Protocol)

Used for inter-domain routing on the Internet, BGP, unlike other routing protocols, maintains a path vector that goes beyond distance and contains a sequence of autonomous systems (ASes), which helps avoid routing loops and execute defined routing control.

4. Hybrid Routing

Example: EIGRP (Enhanced Interior Gateway Routing Protocol)

Merges the distance vector and link state routing, maintaining quick convergence and extensibility.

Network Addressing

Introduction to Network Addressing

What is Network Addressing?

In computer network, a logical or physical address used to uniquely identify a host or machine in a telecommunications network is called a network address. Additionally, nodes in a network may contain hierarchical and structural information, and a network may not be unique.

Types of Network Addresses

Phone numbers, Media Access Control (MAC) addresses, and Internet Protocol (IP) addresses are a few fundamental types of network addresses. It may be symbolic, numeric, or in certain situations, both.

Network Addressing is one of the major responsibilities of the network layer.

Key Characteristics

  • Network addresses are always logical, i.e., software-based addresses.
  • A host is also known as end system that has one link to the network.
  • The boundary between the host and link is known as an interface.
  • A router has two or more links that connect to it and can have multiple interfaces.
  • Each interface is capable of sending and receiving IP packets, so IP requires each interface to have an address.

IP Address Structure

Understanding IP Address Format

IP Address Format

Each IP address is 32 bits long, and they are represented in the form of "dot-decimal notation" where each byte is written in the decimal form, and they are separated by the period.

Example:

An IP address would look like 193.32.216.9 where 193 represents the decimal notation of first 8 bits of an address, 32 represents the decimal notation of second 8 bits of an address.

Network Addressing Example

In the above figure, a router has three interfaces labeled as 1, 2 & 3 and each router interface contains its own IP address.

  • Each host contains its own interface and IP address.
  • All the interfaces attached to the LAN 1 is having an IP address in the form of 223.1.1.xxx
  • The interfaces attached to the LAN 2 and LAN 3 have an IP address in the form of 223.1.2.xxx and 223.1.3.xxx respectively.

Each IP address consists of two parts. The first part (first three bytes in IP address) specifies the network and second part (last byte of an IP address) specifies the host in the network.

Network Addressing Types

Unicast, Multicast, and Broadcast

There are various types of networks addressing, just as there are various dialects of languages. Each of these types-broadcast, multicast, and unicast addressing-has a distinct function in the complex realm of network communication.

1) Unicast Addressing

One-to-One System: The most widely used type of network addressing is unicast addressing. The system is one-to-one; every device connected to the network has a distinct address. The information is sent to a single destination with unicast addressing, which is like sending a letter to a specific person at a specific address. In normal internet traffic, data packets are sent from a single source to a single destination using unicast addressing.

2) Multicast Addressing

One-to-Many System: Multicast addressing simulates sending out invitations to many people simultaneously. In a one-to-many system, data is sent to many devices using a single address. This kind of addressing is especially useful for sending software updates, live video and audio streams, or any other kind of data that needs to be received by several users at once.

3) Broadcast Address

One-to-All System: Conversely, broadcast addressing is the digital counterpart of a public announcement. All the network devices receive data in this one-to-all system. In local area networks (LANs), broadcast addressing usually sends announcements or network requests to every device.

Classful Addressing

IP Address Classes

IP Address Classes

An IP address is 32-bit long. An IP address is divided into sub-classes:

  • Class A
  • Class B
  • Class C
  • Class D
  • Class E

IP Address Structure

An IP address is divided into two parts:

  • Network ID: It represents the number of networks.
  • Host ID: It represents the number of hosts.

In the above diagram, we observe that each class have a specific range of IP addresses. The class of IP address is used to determine the number of bits used in a class and number of networks and hosts available in the class.

Class Determination

The class of an IP address is determined by the first few bits of the address, which define how many bits are used for the network ID and how many are used for the host ID.

Class A Addressing

Large Networks with Many Hosts

Class A Characteristics

In Class A, an IP address is assigned to those networks that contain a large number of hosts.

Address Structure

  • The network ID is 8 bits long.
  • The host ID is 24 bits long.

Bit Pattern

In Class A, the first bit in higher order bits of the first octet is always set to 0 and the remaining 7 bits determine the network ID. The 24 bits determine the host ID in any network.

The total number of networks in Class A = 2^7 = 128 network address

The total number of hosts in Class A = 2^24 - 2 = 16,777,214 host address

Range

Class A IP addresses range from 0.0.0.0 to 127.255.255.255

Class B Addressing

Medium to Large Networks

Class B Characteristics

In Class B, an IP address is assigned to those networks that range from small-sized to large-sized networks.

Address Structure

  • The Network ID is 16 bits long.
  • The Host ID is 16 bits long.

Bit Pattern

In Class B, the higher order bits of the first octet is always set to 10, and the remaining 14 bits determine the network ID. The other 16 bits determine the Host ID.

The total number of networks in Class B = 2^14 = 16384 network address

The total number of hosts in Class B = 2^16 - 2 = 65534 host address

Range

Class B IP addresses range from 128.0.0.0 to 191.255.255.255

Class C Addressing

Small Networks

Class C Characteristics

In Class C, an IP address is assigned to only small-sized networks.

Address Structure

  • The Network ID is 24 bits long.
  • The host ID is 8 bits long.

Bit Pattern

In Class C, the higher order bits of the first octet is always set to 110, and the remaining 21 bits determine the network ID. The 8 bits of the host ID determine the host in a network.

The total number of networks = 2^21 = 2097152 network address

The total number of hosts = 2^8 - 2 = 254 host address

Range

Class C IP addresses range from 192.0.0.0 to 223.255.255.255

Class D and E Addressing

Special Purpose Address Classes

Class D

In Class D, an IP address is reserved for multicast addresses. It does not possess subnetting. The higher order bits of the first octet is always set to 1110, and the remaining bits determines the host ID in any network.

Class E

In Class E, an IP address is used for the future use or for the research and development purposes. It does not possess any subnetting. The higher order bits of the first octet is always set to 1111, and the remaining bits determines the host ID in any network.

Class D IP addresses range from 224.0.0.0 to 239.255.255.255

Class E IP addresses range from 240.0.0.0 to 255.255.255.255

Special Uses

  • Class D addresses are used for multicast applications like video conferencing
  • Class E addresses are reserved for experimental purposes and future use

Address Assignment Rules

Guidelines for Host and Network ID Assignment

Rules for assigning Host ID:

The Host ID is used to determine the host within any network. The Host ID is assigned based on the following rules:

  • The Host ID must be unique within any network.
  • The Host ID in which all the bits are set to 0 cannot be assigned as it is used to represent the network ID of the IP address.
  • The Host ID in which all the bits are set to 1 cannot be assigned as it is reserved for the multicast address.

Rules for assigning Network ID:

When the hosts are located within the same local network, they share the same network ID, which helps identify the specific network that has devices. Proper assignment of a network ID is important to avoid conflict and ensure smooth communication.

Network ID Assignment Guidelines:

  • Reserved category A range (127.x.x.x): No network ID starting with 127 can be assigned, as it is reserved for the limit testing and loopback address used for troubleshooting.
  • Set on all bits 0: A network ID where all bits cannot be assigned to 0 because it reflects a specific host within the local network rather than a valid network.
  • Set on all bits 1: A network ID where all bits 1 are invalid, as this range is reserved for multicast communication, which allows the same packet to be transported to several hosts.

By following these rules, network administrators ensure valid addresses, avoid conflicts, and maintain network stability.

Network addressing is the foundation of communication in modern computer networks. Benefits of a Network Address

Advantages of Network Addressing

One of the major benefits of network addresses is that they ensure the unique identity of each device connected to the network. This specificity guarantees that data is always transported to the right destination without confusion or repetition.

Scalability

Another important benefit is scalability. By assigning structured addresses, the network can easily expand to support the increasing number of equipment. This feature has been important for the global development of the Internet, allowing billions of devices to remain connected.

Efficient Routing

Network addresses also contribute to efficient routing. With a well-organized address, the data packets can be transmitted along the best available path, to reduce delays, reduce the crowd, and improve the overall performance of communication systems.

In addition, the network supports service discrimination through port numbers. This capacity makes it possible to run together on the same device for many applications and services - such as web browsing, sending emails, and streaming materials - without intervention.

By enabling these applications, network addressing supports not only personal and business communication but also the global digital economy. It plays a critical role in ensuring that data flows securely, efficiently, and to the right destination every time.

Disadvantages of Network Address

Challenges in Network Addressing

Despite their importance, network addresses also present some challenges. A major issue is the limited address location of IPV4. Lack of available IPV4 addresses caused exhaustion problems, which in turn created a requirement for IPV6, introducing a large pool of addresses.

Management Complexity

Another defect addressed is the complexity of the management. Addressing and maintaining addresses becomes rapidly difficult in large or dynamic environments, especially when using protocols such as DHCP to automate the process. Mismanagement can result in conflict or connectivity issues.

Security Risks

Because network addresses can be targeted for malicious activities such as IP unauthorized infiltration, the network must be applied to protect the network and ensure data integrity.

These challenges require careful planning, proper network design, and implementation of security measures to ensure reliable and secure network operations.

Network Addressing Problems

Common Issues in Network Addressing

Network addressing plays an important role in ensuring smooth communication, but it often comes with challenges. Some of the most frequent issues include:

IP Address Conflict

These occur when two or more devices share the same IP address, causing connectivity failures. Proper DHCP configurations and stable IP assignment of important systems can prevent such conflicts.

DNS Failures

Inaccurate or incorrect DNS can prevent settings from resolving domain names. Troubleshooting with tools such as NSLOOKUP or switching on reliable DNS servers (eg, Google DNS or Cloudflare) helps maintain stability.

Subnetting Complexity

While subnet improves performance and safety, poor planning can complicate network design and management. Careful configurations and documentation are important to avoid issues.

IP Address Exhaustion

With a limited address pool of IPV4, exhaustion is a risk, especially in large networks. Migration to IPV6 and efficient IP management strategies can reduce this problem.

Security Risk

Weak network configurations highlight the system for unauthorized access and data violations. Regular safety audits, encryption (IPSEC, SSL/TLS), and updated patches are essential for safety.

Solutions for Security Issues

Addressing Network Security Challenges

Using secure protocols, installing firewalls, and conducting routine network monitoring are all necessary to address security issues with network addressing.

Firewalls

By regulating incoming and outgoing network traffic according to pre-established security rules, firewalls protect the network from unauthorized access and potential threats.

Secure Protocols

Protocols like Transport Layer Security (TLS) and Secure Sockets Layer (SSL) help in securing network communications by encrypting data in transit.

Network Monitoring

Frequent network monitoring enables prompt security risk mitigation by assisting in the identification of possible threats or irregularities in network traffic.

Implementing a comprehensive security strategy that combines these solutions helps protect network addressing infrastructure from various threats and vulnerabilities.

Network Addressing FAQs

Common Questions About Network Addressing

1) What is network addressing?
Network addressing is a way to uniquely identify devices, services, or applications in a network so they can communicate with each other.
2) What are the main types of network addresses?
The types of network addressing are as follows:
  • MAC Address: Physical address of a device.
  • Application Address: Human-readable names (like, URLs, emails).
  • Port Address: Identifies specific processes or services.
  • IP Address: Logical address used across networks.
3) What is the difference between a MAC address and an IP address?
MAC Address is hardware-based, permanent, and used inside a local network. IP Address is logical, changeable, and used to identify devices across different networks.
4) What Distinguishes Network IP Addresses from Other Forms of Network Addresses?
Network IP addresses are unique because they serve as a logical, global identifier that enables communication between different networks, not just inside one.
5) What is the difference between IPV4 and IPV6 addresses?
The IPV4 uses a 32-bit address format, which allows about 4.3 billion unique addresses, while the IPV6 uses a 128-bit format, providing an almost unlimited address space to address the IPV4 exhaustion.
